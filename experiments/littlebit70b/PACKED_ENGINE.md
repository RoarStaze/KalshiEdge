# LittleBit packed-factor CPU reference (2026-11-22)

**This is a working mathematical layer prototype with synthetic weights. It is NOT a model, tokenizer, CUDA kernel, Gemma-3 conversion, or trained checkpoint.** It does not require paid cloud GPUs or any downloads.

## Why this milestone matters

Samsung LittleBit and LittleBit-2 replace individual dense linear layers with **two signed binary factors U and V** and learned scales. Samsung's **LittleBit-2 uses the same inference layer** as LittleBit; its Joint-ITQ difference is in initialization/training. Previous attempts used Samsung's evaluation loader, which inflates packed signs into regular tensors. Our goal is to keep factor bits packed while calculating a layer output.

The prototype in `packed_linear.py` implements the **same single-token forward equation**, using row-major, least-significant-bit-first 32-bit packed factor words:

```
h = (x * v2) @ V_sign.T
h = h * (v1 * u2)
y = (h @ U_sign.T) * u1
y += optional_residual + optional_bias
```

- In packed words, a 0-bit encodes +1 and a 1-bit encodes -1.
- Partial 32-bit words are masked, so padding bits never enter calculations.
- The core routine computes a signed dot product from set-bit positions; **no full binary factor matrix is expanded**.
- Handles optional residual factors and bias.
- Requires only the Python standard library; **CPU-only and not performance-optimized**.
- The `storage_bytes` field measures just the 32-bit binary payload, **not** Python object allocations, floating-point scales, unquantized model components, or GPU/CPU runtime memory.

## References and current limitations

- Official [Samsung LittleBitLinear implementation](https://github.com/SamsungLabs/LittleBit/blob/main/quantization/modules/littlebit.py), especially `_compute_forward` and `pack_weights`.
- Official [binary packer](https://github.com/SamsungLabs/LittleBit/blob/main/quantization/utils/binary_packer.py), specifically LSB-first, 32-bit row layout.
- [Samsung LittleBit repository](https://github.com/SamsungLabs/LittleBit), licensed CC BY-NC 4.0. This independent proof-of-concept does not vendor Samsung's implementation.
- Samsung's current code uses right-shift on unpack; older releases had a [reported bit-unpacking bug](https://github.com/SamsungLabs/LittleBit/issues/21). We test signed high-bit and 32-bit boundaries to avoid such corruption.

**Not implemented:** A Gemma 3 27B checkpoint; mapping checkpoint tensors and scales into the prototype; accelerated CUDA kernels; model loading or token generation; quality restoration through quantization-aware training. A verified trained checkpoint and sufficient compute remain separate blockers.
